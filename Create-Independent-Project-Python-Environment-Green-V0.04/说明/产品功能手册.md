# 产品功能手册（V0.04）

给使用者和高程1号看。写的是**代码实际会做的事**，不是宣传语。

生成窗口逐项说明见 `开屏手册.md`。测试对照见 `产品测试用例.md`。

当前锁定版本：**V0.04**。绿色 exe 与 Source 同一轮更新。

---

## 用户能做什么

1. 双击绿色 exe，给一个新文件夹建独立的 `.venv`。
2. 选中文或 English。语言写进该项目的 `ui_lang.txt`，面板文件名和文字跟它走。
3. 在项目里打开「本项目环境」面板：给这个 `.venv` 装库、删库。
4. **可选：** 勾选「双击 .py 用本项目环境」。这不是只改这一个文件夹。

---

## 双击 / 注册表会改电脑哪一块

Windows **不能**只给某一个文件夹改「双击 `.py`」。

本工具只动这一项（且必须勾选 **并且** 确认）：

`HKCU\Software\Classes\VSCode.py\shell\open\command`

改成：

`%LOCALAPPDATA%\IndependentPythonEnv\OpenPyInProject.exe "%1"`

原来的打开命令备份到：

`HKCU\Software\IndependentPythonEnv\Backup\VSCode.py` 的 `open_command`

### 这是整台电脑的挂钩

| 动作 | 范围 |
|------|------|
| 第一次确认勾选 | 改整台电脑的 `VSCode.py`。之后所有双击 `.py` 都会先经过开门程序，直到点「恢复」。 |
| 某个项目的勾 / `use_project_env.on` | 只决定：**这个项目**的 `.py` 要不要用本文件夹的 `.venv` 去开 VS Code。 |
| 未启用的项目（例如后建的、没勾的作业 B） | 仍会先进入开门程序，但开门程序会立刻改走**备份里原来的打开方式**，不会强行开 VS Code，也不会无故开记事本。 |
| 面板「恢复本机双击 .py」 | 整台电脑改回备份，**所有**项目的挂钩一起取消。各项目的标记文件还在，但双击不再经过开门程序。 |

未勾选、取消「新挂钩」确认、或没法改双击：这次创建**不写新挂钩**。若发现旧死命令，确定会清掉后再创建；取消则不创建。开关没打开时不拷开门程序。已经确认过挂钩、这次开关打开：不重写注册表，但会确保 `%LOCALAPPDATA%\IndependentPythonEnv\OpenPyInProject.exe` 还在。若以前已经确认过，挂钩已经在整机上，这次不勾也不会自动拆掉。

### 本机 `.py` 不是 VS Code 打开时

判断依据（只读，不写 `UserChoice`）：先看 `FileExts\.py\UserChoice` 的 `ProgId`；没有再看 Windows 11 的 `UserChoiceLatest\ProgId`（设置里改的默认打开方式写在这里）；再没有才看 `Software\Classes\.py` 的默认 ProgID。若实际不是 `VSCode.py`（例如记事本、`Python.File`）：

- 会明确告诉你：**没法改双击**
- 项目仍创建
- 开关**不会**打开，也不会假装已经打开
- 若 HKCU 里 `VSCode.py` 仍指向本工具开门程序（旧版留下的死命令）：**不是合格状态**。会先问。确定：清掉后再创建（开关不打开）。取消：**不创建**。不把「留下死命令」当成产品行为。不写 `UserChoice`。
- 命令已是开门程序、但本版本还没有确认过：勾选仍会再问。确认后只记下 `wrap_confirmed.on`，不把开门程序写进备份。
- 已经生成的项目里那份 `file_assoc.py` **不会自动变**。旧项目在根目录；新项目在 `工具` / `tools`。不换文件还会弹「没法改双击」。要把 Source 或新绿色工具这一版拷到对应位置，或用新绿色工具再生成一个项目。新项目第一层是面板 exe、说明和手册；其他程序文件在 `工具` / `tools`。

## 开门程序（`OpenPyInProject.exe`）

1. 向上最多 8 层，同时找到 `.venv\Scripts\python.exe` **和** `use_project_env.on` → 视为启用的项目：用 VS Code `-n 项目文件夹` 打开该 `.py`。找不到 VS Code 则改走备份。
2. 否则（没勾的项目、普通文件夹）：**先跑备份里的原命令**。
3. 备份没有或失败：再试 VS Code；再失败才用记事本，避免文件打不开。这是最后兜底，**不是**产品承诺的默认打开方式。
4. 不会 `ShellExecute` 同一个 `.py`（会循环调用自己）。

没有右键菜单「用项目环境打开」。

## 装库会改电脑哪一块

只改**这个项目文件夹里的** `.venv`。不往系统 Python 装。

- 常用库勾选，或粘贴库名。安装前弹出将要装的原名，并提醒核对拼写。
- 会从网上 `pip install` 你确认过的名字。不钉版本。拼错的名字（如 `reqeusts`）确认后仍可能装到错误的包。
- 挡 URL 和 pip 参数；挡不住拼错的 PyPI 名。
- pip 非 0 算失败。列包约 60 秒超时；安装约 300 秒。

## 生成窗口其它规则

- 名称不能用 `\ / : * ? " < > |`，不能以点或空格结尾，不能用 Windows 保留名（`CON`、`PRN`、`NUL`、`COM1` 等）。
- 「保存到文件夹」必须**已经存在**。不会沿途新建一串空目录。默认位置是用户目录下的 `Projects`。
- 新项目的 `.vscode/settings.json` 把终端工作目录设成项目文件夹，并指向本项目 `.venv`。
- 创建失败会删掉这次新建的项目文件夹。
- 英文面板 exe 名叫 `Project Environment.exe`（有空格）。资源管理器双击可以；命令行必须加引号。

## 明确没有的功能

- 不按文件夹做真正的「只改这一个作业」的 Windows 关联（做不到）。
- 不改 `UserChoice`、环境变量、启动项。
- 已经生成的项目里那份 `file_assoc.py` 不会自动换成新版。旧项目在根目录，新项目在 `工具` / `tools`。要拷新文件，或用新绿色工具再生成。
- 运行时不编译 C#。
- 不把绿色包或新项目里的文件设成隐藏。绿色包中文说明书进「说明」，英文说明书进 `docs`；新项目的脚本进「工具」/ `tools`。

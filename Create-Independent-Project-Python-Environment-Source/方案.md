# 独立环境：双击 .py 的完整方案

这份是给人阅读的方案正文。绿色 exe 按版本打在旁边的 Green 文件夹里；源码按版本放在本目录的 `V0.01`、`V0.02`……里。

当前已落地绿色版 **V0.03**。无版本号的 Green 文件夹视为 **V0.01**。

## 要解决什么

每个项目已经能生成独立环境（项目文件夹 + `.venv` 工具箱）。  
问题是：关掉 VS Code 后再双击 `.py`，Windows / VS Code 只打开这一个文件，点运行会用系统默认 Python（或 uv 那份），而不是这个项目的 `.venv`。

`.py` 不论是在本文件夹新建的，还是从别处粘进来的，规则相同。  
程序文件放在 `.venv` **旁边**（或项目子文件夹里），不要放进 `.venv`。

## 开关是按项目的，不是全电脑总开关

生成窗口上有一项，默认不勾：

**在此项目中，双击 .py 时使用本项目的独立环境**

| 生成这个项目时 | 双击这里的 `.py` |
|----------------|------------------|
| 勾了 | 用这个项目自己的 `.venv` |
| 没勾 | 用系统默认 Python |
| 文件不在任何独立环境里（例如桌面上单独一个） | 用系统默认 Python |

作业 A 勾了、作业 B 没勾，互不影响。

## 当时没勾，后来要改

独立环境在创建时就已经在，不用重建文件夹。

每个项目里**无论勾没勾**都留下两个入口：

- **启用：双击用本环境**
- **关闭：双击用系统 Python**

事后双击「启用」，等于补上当初没勾的决定；以后在这儿双击 `.py` 都走本项目 `.venv`。  
事后双击「关闭」，这个项目回到系统默认 Python；别的项目不受影响。

没有单独的右键菜单。只靠生成时的勾，以及文件夹里的启用/关闭。

## 背后必须有的开门程序（用户看不见总开关）

Windows 不能只给某一个文件夹改「双击 `.py`」。  
所以本机要有一个很小的开门程序：双击任何 `.py` 时先看这个文件所在项目有没有启用。

- 已启用 → 用 VS Code 打开**整个项目文件夹**并打开这个文件，点运行走该项目 `.venv`
- 未启用，或附近没有 `.venv` → 仍按系统默认（VS Code 只打开文件 / 系统 Python）

开门程序不是界面上的总开关，只负责读每个项目自己的启用标记。

## 每个新项目文件夹里有什么

生成工具创建时写入：

1. `.venv`
2. `.vscode/settings.json`（钉死本文件夹用 `.venv`）
3. 启用 / 关闭 两个入口（始终都有）
4. 启用标记：勾了或事后点了「启用」才打开；没勾或点了「关闭」则关上
5. `维护本项目的库.bat` / `维护本项目的库.py`（V0.03：给这个项目的 `.venv` 装库、删库）

不自动生成作业 `.py`。你自己新建或粘贴。

## 维护本项目的库（V0.03）

入口在**生成出来的项目文件夹**里，不在绿色 exe 那三个文件里。

- 双击 `维护本项目的库.bat` 打开窗口
- 常用库可勾选；没有的库名自己粘贴
- 列表只信这个项目 `.venv` 里 pip 的真实结果
- 没装完不算已安装；关掉窗口会停掉当前安装
- 只装进本项目 `.venv`，不装进系统 Python
- pip / setuptools / wheel 不能删

## 双击、打开文件夹

- **双击 `.py`**：看该项目当前是否启用（生成时的勾，或后来的启用/关闭）。
- **打开整个项目文件夹再运行**：不依赖双击；有 `.vscode/settings.json` 时更稳。

## 明确不做

- 不做成全电脑一次总开关。
- 不把所有项目共用一个 Python。
- 不做右键「用项目环境打开」（避免打开方式里出现重复项）。
- 没有明确要求时，不提交 git、不上传 GitHub。
